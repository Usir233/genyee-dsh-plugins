# 桌面端验证清单（两台电脑，Windows / macOS）

本清单在两台同一内网的真实电脑上验证 `@genyee/dsh-keyhub` 0.2.0：一台做**管理员**，一台做**员工**。单机上的同类验证已在开发时完成（两个独立的 DSH 数据目录、真实 DeepSeek API）；这里要确认的是跨机器网络、防火墙和桌面端安装。

每一步后面的 **【记录】** 是需要发回的内容。遇到和描述不一致的情况，停下来，把截图和报错原文发回即可。

## 准备

| 项目 | 管理员电脑 | 员工电脑 |
|---|---|---|
| DSH 桌面端 | `0.2.2-alpha.2` | `0.2.2-alpha.2` |
| 插件包 | `releases/keyhub/genyee-dsh-keyhub-0.2.0.tgz` | 同左 |
| DeepSeek Key | 一个测试用 Key，账户里留少量余额 | 不需要 |

下文用 `<DSH>` 表示 DSH 的数据目录：macOS 为 `~/.dsh`，Windows 为 `%USERPROFILE%\.dsh`。在 YAML 文件里写 Windows 路径时用正斜杠，例如 `C:/Users/张三/keyhub/relay.crt`。

## 一、管理员电脑

**1. 安装插件**

打开 DSH → 左侧**插件** → **添加插件**，填入 `.tgz` 的绝对路径后安装。

【记录】插件列表里是否出现“Genyee 密钥中心”。

**2. 查本机内网 IP**

- Windows：执行 `ipconfig`，看“IPv4 地址”。
- macOS：执行 `ipconfig getifaddr en0`；有线网络可能是 `en1`。

下文用 `10.0.0.8` 代指这个 IP。

**3. 生成证书**

在终端执行下面的命令。`T` 代表 `node <DSH>/profiles/desktop/node_modules/@genyee/dsh-keyhub/lib/tools/admin-tools.js`；管理员电脑需要 Node.js 24 以上。

```sh
T make-cert --ip 10.0.0.8 --out ~/keyhub
```

**4. 打开管理员模式**

打开 `<DSH>/profiles/desktop/cordis.patch.yml`，在文件末尾追加下面的内容（路径换成实际值）。如果文件内容只有 `[]`，先删掉 `[]`。

```yaml
- insert:
    - id: genyee-keyhub-admin
      name: '@genyee/dsh-keyhub'
      config:
        role: admin
        listenHost: 10.0.0.8
        listenPort: 8443
        tlsCertFile: C:/Users/admin/keyhub/relay.crt
        tlsKeyFile: C:/Users/admin/keyhub/relay.key
        ledgerFile: C:/Users/admin/keyhub/ledger.db
```

完全退出并重新打开 DSH。如果弹出防火墙提示，选择**允许**；Windows 至少勾选“专用网络”。

【记录】是否弹出防火墙提示、选择了什么；左侧栏是否出现“Genyee 密钥中心”。

**5. 在管理页面配置**

打开左侧栏“Genyee 密钥中心”，依次操作：

1. **部门**：新增部门，ID 填 `rd`，名称填“研发部”；点“设置 Key”，粘贴测试 Key 并保存。状态应变为“已配置”。
2. **价格**：按 DeepSeek 官网价格分别填写 `deepseek-flash` 和 `deepseek-v4-pro`。
3. **员工**：新增“管理员”和“测试员工”，各复制一次弹出的接入码。接入码只显示一次。
4. **服务状态**：点“查询余额”，应显示账号余额。

然后在“设置 → Genyee 密钥中心”中粘贴“管理员”的接入码，保存后应显示“已连接管理端”。

【记录】服务状态页截图；新建对话发送“用一句话介绍你自己”是否正常回复；用量页是否出现记录。

## 二、员工电脑

**6. 安装并填写接入码**

同第 1 步安装插件。打开“设置 → Genyee 密钥中心”，粘贴“测试员工”的接入码并保存。

【记录】设置页显示的连接状态。显示“已连接管理端”就说明管理员电脑的转发端口在内网可以访问。

**7. 员工对话**

新建对话，确认模型选择器里选的是 **Genyee** 路由，发送“你好”。

【记录】是否正常回复。

## 三、管控行为

以下操作都在管理员电脑的管理页面上进行，员工电脑的 DSH 保持打开。

**8. 额度用完**

“额度”页给“测试员工”设置每月 `0.000001` 元。员工发一条消息（第一条可能仍会成功），再发第二条。

【记录】员工界面的报错原文，期望为“你的本月额度已用完（……），请联系管理员”。之后点“取消额度”恢复。

**9. 模型限制**

在“员工”页编辑“测试员工”，取消“全部已定价模型”，只勾选 `deepseek-v4-pro` 并保存。员工用 `deepseek-flash` 发消息。

【记录】报错原文，期望为“你没有使用模型 deepseek-flash 的权限，请联系管理员”。之后恢复为“全部已定价模型”。

**10. 停用后立即中断**

员工发送“写一篇 2000 字的文章介绍长城”，在回复还在输出时，管理员在“员工”页点“停用”。

【记录】员工的回复是否在约 1 秒内停止，以及显示的文字（期望为“授权码无效或已被管理员停用，请联系管理员”）。之后点“启用”恢复。

**11. 管理员关闭 DSH**

管理员完全退出 DSH，员工发一条消息。

【记录】报错原文，期望包含“无法连接管理端”和“请确认管理员的 DSH 已打开”。
